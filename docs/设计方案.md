**喷涂完整流程**

| 阶段 | GUI主要内容 | 完成门槛 |
|---|---|---|
| 0 联合运动 | 当前已有 XYZ、舵机、联合执行 | 用户确认运动与线束无异常，已完成 |
| 1 喷头连接 | 控制器连接、固件、供电、DISARM、通信日志 | 控制器在线，复位输出安全 |
| 2 静态喷射 | 单喷嘴、单色、喷射次数、间隔、喷嘴测试图 | 波形通过，获得喷嘴健康表和喷距参数 |
| 3 工件与曲面 | 复用 STL、拍照、定位、床面 Z | 形成有效 `SurfaceContext` |
| 4 图案配置 | PNG/JPG、尺寸、位置、旋转、CMY、抖动预览 | 形成带版本号的图案栅格 |
| 5 喷涂规划 | 扫描带、舵机角、有效喷嘴、速度、间隙 | 生成 `CoatingPlan`，无越界点 |
| 6 仿真预检 | 3D预览、舵机范围、坡度、间隙、碰撞、干运行 | 自动检查通过并由用户确认装夹 |
| 7 任务执行 | 上传、启动、进度、暂停、停止、急停 | 任务明确完成、停止或失败 |
| 8 结果验收 | 拍照、偏差、缺线、喷嘴状态、参数记录 | 保存验收结论并冻结任务版本 |

阶段 3 不应复制九千多行的曲面页面代码。应逐步提取共享的 `SurfaceContext`，喷涂页只显示摘要、最近定位结果和“进入曲面设置”。

**阶段状态**

每个阶段使用结构化状态：

```dart
enum WorkflowStageStatus {
  locked, available, current, running,
  completed, stale, failed,
}
```

切换规则：

1. 向前只能进入 `available` 阶段，必须满足前一阶段的验收门槛。
2. 已完成阶段可以随时返回查看。
3. 执行期间锁定普通切换，只保留暂停、停止和急停。
4. 修改上游数据时，不直接删除旧结果，而是将下游标为 `stale`。
5. `stale` 阶段保留旧预览，但禁止执行，直到重新生成。
6. 软件命令成功不等于硬件验收通过。物理阶段必须记录人工确认。
7. 重启应用后根据任务清单恢复到首个未完成或已失效阶段。

阶段视图与工作区视图需要分开：

```text
selectedStage       当前业务阶段
selectedWorkspace   当前阶段内部的预览模式
```

例如“工件与曲面”阶段内部仍可自由切换 STL、照片、定位、轨迹预览，但不能因此把整个喷涂任务误判为已进入规划阶段。

**失效关系**

- 修改舵机/TCP/喷头配置：阶段 5–8 失效。
- 修改 STL、定位或床面 Z：阶段 5–8 失效。
- 修改图案、尺寸、颜色或抖动：阶段 5–8 失效。
- 修改扫描速度、点距或喷嘴选择：阶段 6–8 失效。
- 仅缩放、平移预览或改变显示图层：不影响任何产物。
- 已经执行过的任务发生上游修改时，保留历史运行记录，创建新修订版。

**任务数据**

每次喷涂建立独立任务目录：

```text
coating_jobs/<job_id>/
  manifest.json
  hardware_profile.json
  surface_context.json
  artwork.json
  coating_plan.json
  preflight.json
  run.json
  verification/
```

`manifest.json` 保存当前阶段、人工验收记录、各产物路径和依赖摘要。`SharedPreferences` 只保存最近任务 ID，不作为阶段完成依据。
